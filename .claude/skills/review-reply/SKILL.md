# Review Reply

팀 규칙: **PR 승인 전에 모든 코멘트를 처리한다. 반영하지 않을 경우 답글에 이유를 달고 resolve한다.**
그래서 이 스킬의 완료 조건은 "미해결(unresolved) 스레드 0개"다.

## 절차

1. **스레드 수집**

   ```bash
   bash .claude/skills/review-reply/scripts/threads.sh list <pr>
   ```

   미해결 스레드만 JSON으로 나온다 (`threadId`, `path`, `line`, `comments[{id, author, body}]`). 스레드의 **마지막 코멘트**까지 읽는다 — 이미 대화가 오간 스레드일 수 있다.
   리뷰 본문(인라인이 아닌 전체 코멘트)은 `gh pr view <pr> --comments`로 확인한다.

2. **분류** — 각 스레드를 하나로 판정한다:

   | 판정        | 기준                                                                       |
   | ----------- | -------------------------------------------------------------------------- |
   | 반영        | 버그·규칙 위반·명백한 개선. `[필수]`는 원칙적으로 반영                     |
   | 미반영      | 의도된 설계, 범위 밖(별도 이슈로), 리뷰어의 오해, 트레이드오프상 현행 유지 |
   | 질문 답변   | `[질문]` — 코드 변경 없이 설명                                             |
   | 사용자 판단 | 제품 방향·요구사항이 걸린 결정 — 임의로 정하지 말고 사용자에게 묻는다      |

   분류표를 사용자에게 먼저 보여주고 진행한다(오케스트레이터에서 "자동 진행"으로 호출된 경우 사용자 판단 항목만 묻는다).

3. **반영 작업**
   - 코드 수정 후 `commit-message` 스킬 규칙으로 커밋한다. 코멘트 하나당 커밋 하나가 기본이고, 같은 성격의 사소한 수정 여러 개는 묶어도 된다.
     - 예: `fix: 택배 목록 빈 배열 처리 누락 수정`, `refactor: parcel 슬라이스 public API 경유로 import 변경`
   - lint/typecheck를 돌려 깨지지 않았는지 확인한다.
   - `git push`.

4. **답글 + resolve** — push가 끝난 뒤에 답글을 단다(답글에 적은 커밋이 원격에 있어야 링크가 동작한다).

   ```bash
   bash .claude/skills/review-reply/scripts/threads.sh reply <pr> <commentId> <body-file>
   bash .claude/skills/review-reply/scripts/threads.sh resolve <threadId>
   ```

   `commentId`는 스레드 **첫 코멘트**의 id(REST databaseId)다.

   답글 형식 (한국어, 존댓말, 짧게):
   - 반영: `반영했습니다. <무엇을 어떻게 바꿨는지 한 줄> (abc1234)`
   - 미반영: `이번 PR에서는 반영하지 않았습니다. <이유>. <대안/후속 계획 — 예: #34 이슈로 분리했습니다>`
   - 질문 답변: `<답변>` — 답변만으로 해소되면 resolve, 리뷰어 추가 확인이 필요해 보이면 resolve하지 않고 보고에 남긴다.

   미반영 이유는 "나중에 할게요"처럼 비어 있으면 안 된다. 리뷰어가 납득할 수 있는 근거(설계 의도, 범위, 성능 측정, 다른 위치에서 처리됨 등)를 적는다.

5. **확인**: `threads.sh list <pr>`를 다시 돌려 남은 스레드를 보고한다.

## 하지 않는 것

- 리뷰어 코멘트 수정/삭제
- 사용자 판단 항목을 임의로 결정하고 resolve
- force push (리뷰어가 보던 커밋이 사라진다) — 새 커밋으로 쌓는다
